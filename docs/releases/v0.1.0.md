# renewal v0.1.0

Insurance renewal comparison and record layer, for one agency.

Documents arrive by email, upload, or bulk import. Each one is stored, read,
dated, labelled and matched to a client. Some become structured policy terms.
When a renewal lands on a policy that already has one, the comparison between
them builds itself and says what changed and whether it matters.

Two rules the whole system obeys: no model output is allowed to gate retrieval,
so a document nobody could classify or match is still searchable and its dates
still appear on the calendar; and state is computed at read time rather than
stored, because a stored status lies the moment somebody fixes the thing it
describes.

Full explanation: `docs/how-it-works.md`.

## What is in it

- **Intake** — a read-only IMAP poller, a webhook for hosted mail, manual
  upload, and bulk import of an archive. One pipeline behind all four.
- **Reading** — text extraction with local Tesseract OCR for scans, two-pass
  date extraction, classification into eleven document kinds, client matching.
- **Extraction** — typed field paths read from declarations, endorsements and
  quotes, with every field carrying the source text it claims to quote. A field
  whose quote is not on the page it cites is kept at zero confidence, never
  silently trusted.
- **Comparison** — up to five frozen terms side by side, differences classified
  material / informational / noise by tunable rules, arithmetic-only premium
  attribution, and a draft explanation for a licensed human to edit.
- **The record layer** — an inbox of four buckets computed at read time, search
  over four unioned paths, a month calendar with a subscribe-only `.ics` feed,
  and an attention queue that over-flags on purpose.
- **Operations** — session auth on every route, a `user_id` on every decision
  table that shows on the page, a daily summary email carrying counts and no
  client detail, and blob encryption at rest.

898 tests.

## Installing it

```bash
tar xzf renewal-0.1.0.tar.gz && cd renewal-0.1.0
./scripts/install.sh
```

Needs Python 3.11+, PostgreSQL 15+, and Tesseract for OCR of scans. The script
checks for all three, builds the virtualenv, writes a `.env`, generates a blob
encryption key, creates the database, migrates it, and offers to make the first
account. It is safe to re-run.

You must then put an API key in `.env` — the application builds its model
client at import and will not start without one. `deploy/renewal.service` and
`deploy/renewal.nginx` cover running it as a service behind TLS.

## Please read before pointing this at real documents

**Extraction accuracy on real carrier paperwork has not been measured.**
`evals/baselines/` is empty. The failure mode that matters is not a crash: it
is a confidently wrong premium in a comparison. Run it against documents whose
answers you already know before trusting one you do not.

**No real mailbox has been polled.** The IMAP path is tested against a fake
server object, which proves the sequencing and the dedupe, not somebody's
actual MIME.

**Documents are sent to a model provider.** With `PROVIDER=anthropic`, every
declarations page goes to Anthropic for extraction and drafting. OCR stays
local; the documents do not. `PROVIDER=ollama` keeps everything on the machine
at some accuracy cost. `PRIVACY.md` has the full table — read it before this
holds anyone's records but your own.

**Back up three things separately:** the database, the blob directory, and
`BLOB_ENCRYPTION_KEY`. A backup that travels with its key is not encrypted, and
a lost key means every stored document is unreadable by anyone, permanently.

## Known limits

- One agency. The agency id is hardcoded in three places.
- No way to export or send a comparison; the workflow ends at the screen.
- No signup route — accounts are made from a shell, on purpose.
- `renewal_run` is a dead table kept for old rows.
- **Windows is untested.** The application is portable Python — no Unix-only
  imports, no posix paths, no shelling out — and `scripts/install.ps1` sets it
  up there, but nothing in this project has ever been run on Windows. That
  claim is read off the code, not off a machine. WSL2 is the path with no
  unknowns in it. Running on boot is systemd on Linux and NSSM or a Scheduled
  Task on Windows.
