# renewal v0.2.0

A front page, and a way to find out whether any of this is working.

Everything in [v0.1.0](v0.1.0.md) still applies — including the warnings, which
have not been answered by this release. Read those before pointing it at
anybody's records.

## A dashboard at `/`

The application used to open onto the inbox: a list of documents in arrival
order, answering *what came in*. The question somebody actually has on a
Tuesday morning is *what do I have to do*. So `/` is now a front page and the
inbox has moved to `/inbox`.

- **Four counts** — needs you, dates inside thirty days, in flight, arrived
  this week. Those are the only numbers in the system that change what happens
  next; the rest of a dashboard's usual row is invention. A count of zero drops
  to secondary ink, so the row reads as "these two need me" without anything
  being coloured.
- **The two queues that decide a morning**, side by side: what is waiting on a
  person, and what is coming at them.
- **The comparisons it built without being asked**, with prior and renewal
  premium and the change between them. The only panel reporting work already
  done, and the only evidence on the page that the automatic half runs at all.
  Increases are red; a premium that fell is good news and does not need a
  signal spent on it. A premium that does not parse shows nothing rather than
  a fabricated hundred-percent drop.
- **A line above all of it** when no mailbox is connected, or when the mailbox
  has stopped answering. A quiet week and a forwarding rule that broke on
  Thursday are indistinguishable from every other panel on the page.

The six navigation links became a rail down the left. They had already filled
the masthead, and the count beside each one is what decides where to go — a
horizontal nav has nowhere to put it. Breadcrumbs moved above the page
heading. Structure borrowed from Cloudflare's dashboards; the ink is
unchanged — no cards, no radius, no shadows, one red still meaning one thing.

## Usage tracking, and an export

Most of what is worth knowing was already being recorded, because this
application records decisions rather than states: a correction says what the
model produced and what the truth was, a manual link says the match was wrong,
a dismissed date says the extractor found something that was not there. Those
rows are an evaluation set that writes itself, and nothing was reading them.

`USAGE_TRACKING` (on by default) adds the half the database could not know —
which screens, how often, in what order, how slow.

```bash
python -m scripts.usage_report --days 30 --out usage.json
python -m scripts.usage_report --check      # what it would contain
```

Six sections: what arrived, what the pipeline did with it, where the extractor
was corrected **by field path**, what was accepted and what was thrown away,
which screens were used and in what order, and what was started but not
finished.

**The file is built to leave.** It is meant to be mailed, pasted into a chat,
or handed to a model for a second opinion, so it carries counts, distributions,
durations and field paths — and no client name, no filename, no premium and no
document text. A page view is stored as its route *template*, so
`/documents/{document_id}/review` is one row about a screen and never a row
about a document. There is a test that fails if a client's name can reach the
export.

**Whoever uses the application should be told this is on.** It is their working
day being counted.

## Also

- `TESSERACT_CMD` names the OCR binary when PATH does not — which is the normal
  case on Windows, where the installer puts `tesseract.exe` under Program Files
  and leaves PATH alone. Without it every scanned page failed there.
- The source distribution now carries `scripts/install.ps1`.

## Upgrading from 0.1.0

```bash
git pull && ./scripts/install.sh      # or scripts\install.ps1 on Windows
```

One migration (`usage_event`), and it is reversible. Nothing else changes on
disk. If anything bookmarked or linked to `/` expecting the inbox, it now wants
`/inbox`; every redirect inside the application moved with it.

## Still true, and still the point

Extraction accuracy on real carrier documents is **unmeasured** —
`evals/baselines/` is empty. No real mailbox has been polled. Windows is
untested. This release makes it easier to find out whether the thing works; it
does not answer the question.
