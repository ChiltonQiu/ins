# renewal v0.2.2

Windows with no prerequisites. Download, unpack, double-click, wait.

Everything in [v0.2.1](v0.2.1.md), [v0.2.0](v0.2.0.md) and
[v0.1.0](v0.1.0.md) still applies, including the warnings.

## What changed

v0.2.1 gave Windows a double-clickable installer that still expected Python
and PostgreSQL to be there already — three downloads, two installers and an
administrator password before anybody saw the application. This removes that.

**Double-click `install.cmd`.** It now installs what is missing:

- **Python**, when absent, is installed **for this account only**
  (`InstallAllUsers=0`), into `AppData`.
- **PostgreSQL**, when absent, is **not installed at all**. The binaries are
  unpacked into `runtime\` inside the application folder, `initdb` makes a
  cluster there, and it listens on **127.0.0.1:5433**. No Windows service, no
  superuser password, nothing registered on the machine, and the standard port
  left free for a PostgreSQL that may already own it.
- A computer that already has either one is left alone and uses it.

**Nothing asks for an administrator password.** Deleting the folder removes
everything except the per-user Python.

The download is about **315 MB** on a machine with neither, and that is the
slow part — allow ten minutes on a domestic connection. A machine that already
has both fetches nothing.

`install-no-downloads.cmd` is the previous behaviour, for somebody who would
rather install the prerequisites themselves: it fails with a download link
instead of fetching.

## Still the same afterwards

A **Renewal icon** on the desktop and in the Start Menu, and the application
starts itself when that account signs in. The icon opens a browser at it,
starting it — and the private database — first if they are not already up.

One value still has to be filled in before it will start: `ANTHROPIC_API_KEY`
in `.env`. The application builds its model client when it loads.

## Read this before you try it

**None of this has been run on Windows.** There is no Windows machine and no
PowerShell runtime where it was written. It is careful rather than proven, and
this release does *more* than the last one — downloading, running an
installer, creating a database cluster — so there is more that can go wrong on
first contact.

What is verified: the download URLs resolve and are the sizes stated; the
packaging pipeline stages from the source distribution and refuses to build if
an entry point is missing; `python -m uvicorn renewal.app:app` serves `/login`
with a `200`, which is how the launcher decides the application is up.

If something goes wrong, two things are worth capturing:

1. **The whole `install.cmd` window.** It pauses at the end for exactly this
   reason — the error is above the pause.
2. **What the application says when started by hand**, which is where a
   configuration problem names itself:

   ```powershell
   cd <the folder>
   .venv\Scripts\python -m uvicorn renewal.app:app --port 8000
   ```

And if the database is what failed, `runtime\postgres.log` has the reason at
the end of it.

## The `.exe`

`packaging/renewal.nsi` builds a per-user `Renewal-x.y.z-setup.exe` — the same
installation with a wizard around it. It is not attached to this release: NSIS
was not available on the machine that cut it. `./packaging/build-installer.sh`
builds it anywhere `makensis` is.

## Unchanged

Extraction accuracy on real carrier documents is still unmeasured, and no real
mailbox has been polled. This release is about getting the thing running in
front of somebody. It still does not tell you whether it is any good — that is
what `scripts/usage_report.py` is for, a week later.
