# renewal v0.2.6

**Download `Renewal-0.2.6-setup.exe` and double-click it.**

This is the first release whose Windows install has been run from start to
finish on a Windows machine. Every earlier one was written from the code: the
first real install, on a real PC, stopped five times, each for a different
reason. All five are fixed, and a CI job now does on every push what that
person had to do by hand.

## What was broken

- **The installer would not start.** `bootstrap.ps1` contained an em dash.
  Windows PowerShell 5.1 reads a script with no byte-order mark as
  Windows-1252, where the last byte of an em dash is a closing curly quote —
  which it accepts as the end of a string. Every file Windows runs is ASCII
  now, and a test keeps it that way.
- **It hung forever after "Cluster created".** The database is started with
  `pg_ctl`, whose output was piped away; the server inherits that pipe, and
  PowerShell waits for a pipe to close. It never does while the database is
  up. The desktop icon would have hung the same way every morning.
- **"PostgreSQL is not installed" — with it running.** The second half of the
  installer was never told where the first half had put the private database.
- **Running it again failed.** The re-run's "database already exists" is
  harmless, but Windows PowerShell 5.1 turns anything a program writes to its
  error output into a fatal error under the scripts' settings. Five commands
  had that shape.
- **Starting again after a reboot could fail** on a machine whose environment
  names another PostgreSQL's port.

Also: `runtime\install.log` now covers the whole install, not just the first
half, and the `.exe` exits with an error code when setup fails instead of
reporting success.

## Tested

On a clean Windows Server 2025 runner, with its own PostgreSQL hidden, on every
push (`.github/workflows/windows-install.yml`):

- the tarball, unpacked into `Downloads\renewal (1)\`, installed with
  `install.cmd`, then installed **again** over itself;
- sign-in;
- the database stopped, as after a reboot, and started again by the desktop
  icon's script;
- the `.exe`, built on Linux the way this release was, installed silently and
  started from its desktop shortcut.

What CI cannot do is click: the wizard's pages and the browser opening have
not been seen by anybody on this release.

## Still true

An API key still has to be pasted into `.env` by hand, in the installation
folder (`%LOCALAPPDATA%\Renewal`), before the application will start. A setup
page to replace that is the next release.

## Upgrading from a failed 0.2.5 install

Restart the computer first, so the database the old attempt started is no
longer running, then delete the old folder and run the `.exe`. Python and
Tesseract, if they were installed, can stay.
